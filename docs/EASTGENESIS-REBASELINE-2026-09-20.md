# EastGenesis 重定位与工作台重做

## 已确认方向

1. CaoGen 产品更名为 **EastGenesis**。EastGenesis 是产品名；内部迁移期间保留 `caogen` 存储键、协议名和历史文件名，避免破坏已有本地数据。
2. Web 启动页、Electron 启动页、侧栏品牌、favicon、桌面图标和安装包显示统一使用 EastGenesis 品牌资源。
3. CaoGen 源码继续作为主线实现；`2026-9-17-codex-workbuddy-ai/outputs/EastGenesis-Desktop` 作为功能和视觉参考，不直接覆盖主线源码。
4. 3D 故宫从当前产品主路径移除。现有场景、角色和 PalaceScene 代码保留为隔离的后续实验资产，不参与默认导航、首屏、任务创建和发布验收。
5. 当前首要目标是一个真正可用的 EastGenesis 工作台闭环。工作台可用性优先于扩展功能数量和 3D 形态。

### 品牌视觉基线

本轮用户提供的品牌图稿作为 EastGenesis 的视觉验收基线：

- 主标使用红金 `G` 与中心星芒；深色桌面图标使用深红/黑底，浅色图标使用白底。

- 工作台视觉参考为用户提供的三栏布局图：左侧任务，中间当前工作，右侧文件/产物/审查；这只是布局参考，交互以本文件的闭环验收为准。

## 首版工作台闭环

用户打开应用后只需要理解一条路径：

`新建任务 → 选择工作类型 → 输入目标 → 选择目录/项目 → 运行 → 查看过程 → 检查结果 → 继续修改或交付`

### 主界面结构

- **左侧：任务与项目**。新建任务、搜索任务、最近任务、项目目录；不再同时暴露 Work Inbox、Studio、Assistant、Video 等多个一级工作模式。
- **中间：当前任务**。消息、运行状态、审批、失败、恢复和继续输入都在同一条时间线上。
- **右侧：当前任务上下文**。默认显示产物；需要时切换到文件、差异、终端、浏览器、任务计划和验收。没有上下文时不显示空白工具面板。
- **底部：输入与运行控制**。输入框、工作类型、模型/路由、权限档位和发送/停止按钮必须在同一位置；停止、暂停、重试和继续不藏在深层菜单。

### 首批工作类型

- 通用 Agent：文件、终端、浏览器、Office 和 MCP/Skills 可按权限组合使用。
- 编程与修复：项目目录、代码修改、终端、差异和测试结果。
- Office 文档：读取或生成 DOCX/XLSX/PPTX，结果可打开和预览。
- 网页研究：搜索、读取、引用和报告。

工作类型是路由提示和界面预设，不创建四套任务系统。所有类型都写入同一条 Goal/WorkItem/Run/Artifact/Acceptance 链。

## 从 EastGenesis 借鉴的能力

优先移植可直接降低操作负担的能力：

1. 简体中文默认界面和稳定的 EastGenesis 品牌资源链。
2. 单一工作台布局：任务列表、中央对话、右侧产物/审查、底部终端。
3. 模型与连接设置：Provider、协议、模型、能力、路由、费用和健康状态集中管理。
4. 通用 Agent 工作区：不要求先创建 Git 项目，也能处理本地资料和文件。
5. Office 结果卡：打开文件、预览文本、保留来源和权限边界。
6. Automations：一次性、周期性和每日任务，保留审批和重启对账。
7. Skills & MCP 管理：安装、启停、权限范围和敏感配置隔离。
8. 终端、差异、浏览器和审查的同任务连续性。
9. 本地 Provider Gateway 的能力筛选、有限故障切换和请求历史。

暂不移植：T3/EastGenesis 的账号体系、远程托管服务、专有云能力、全量移动端、官方产品 parity 声明。

## 工作台重做顺序

### W0：清理主路径

- 首屏只保留 EastGenesis 工作台和新建任务。
- 隐藏故宫、Video 和不完整的扩展入口，不删除后端能力。
- 统一当前任务身份、项目目录、工作类型和输入草稿。
- 消除“没有任务时打开文件/差异/终端”的空面板。

### W1：完成最小可用闭环

- 新建通用任务并发送第一条消息。
- 选择或创建项目目录。
- 明确显示模型/连接、权限和是否会修改文件。
- 运行中显示步骤、工具调用、审批和停止按钮。
- 完成后显示产物、文件差异、测试结果和下一步操作。
- 失败后显示原因、重试、换路由、暂停和人工接管。
- 重启应用后恢复当前任务，不丢草稿和运行状态。

### W2：补齐高频工作能力

- 编程与修复任务的文件、差异、终端和测试回路。
- Office 生成与预览回路。
- 网页研究来源回路。
- 模型设置、路由预览、费用和连接健康回路。
- Automations、Skills/MCP 和通用工作区入口。

### W3：可用性验收

同一候选至少完成以下人工任务：

1. 新建任务并让 Agent 读取项目、修改文件、运行测试、查看差异。
2. 任务中途追加要求，确认上下文、草稿和权限保持。
3. 工具失败后停止、重试或换路由，确认旧结果不会覆盖新运行。
4. 生成一个 Office 文件并打开预览。
5. 关闭并重启应用，继续原任务并保留产物和待处理事项。

未完成上述任务前，不再扩展新的一级模式，也不把类型检查或 fixture 通过当作工作台可用。

## 3D 后续方向

3D 不再是当前应用的工作入口。后续若重启该方向，单独设计为仿古明朝风格的 3D 游戏化工作空间：场景、角色、任务、交互和性能作为独立产品切片验收；不得把装饰性场景重新伪装成任务系统。
